| 项目 | 内容 |
|---|---|
| 模块编号 | MOD-11 |
| 负责需求 | FR-10（含 `04` 补充项 FR-10.5、FR-10.6） |

| 依赖模块 | MOD-10（审计）、MOD-02（对象归属信息） |
| 被依赖 | MOD-09（数据权限过滤）、MOD-08（责任人关联） |

---

## 1. 职责与边界

### 1.1 职责

1. **平台用户体系**：用户、认证、登录
2. **功能权限**：角色与操作权限（RBAC）
3. **数据权限**：按数据源/库/表粒度控制可见性
4. **多租户隔离**
5. **操作审计**（经 MOD-10 落盘）

### 1.2 边界（不做）

- **不做业务库内的账号权限分析**（属 MOD-08）
- 不做业务权限策略的自动判定（只提供策略配置与过滤能力）

> **口径区分**：MOD-08 分析「业务库里谁有什么权限」；MOD-11 管理「平台上谁能看什么」。二者通过 `app_user` 关联（FR-6.7）。

## 3. 数据模型

```sql
CREATE TABLE app_user (
    id            BIGINT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
    tenant_id     BIGINT NOT NULL DEFAULT 0,
    username      TEXT   NOT NULL,
    display_name  TEXT,
    email         TEXT,
    credential_hash TEXT,              -- 平台自身口令哈希
    auth_source   TEXT   NOT NULL DEFAULT 'local',  -- local / ldap / oauth
    external_id   TEXT,
    status        TEXT   NOT NULL DEFAULT 'active',
    last_login_at TIMESTAMPTZ,
    created_at    TIMESTAMPTZ NOT NULL DEFAULT now()
);
CREATE UNIQUE INDEX uq_appuser_name ON app_user (tenant_id, username);

CREATE TABLE role (
    id          BIGINT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
    tenant_id   BIGINT NOT NULL DEFAULT 0,
    role_code   TEXT   NOT NULL,
    role_name   TEXT   NOT NULL,
    description TEXT,
    created_at  TIMESTAMPTZ NOT NULL DEFAULT now()
);
CREATE UNIQUE INDEX uq_role_code ON role (tenant_id, role_code);

CREATE TABLE permission (
    id          BIGINT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
    perm_code   TEXT   NOT NULL,     -- datasource:read / sample:execute / classification:write ...
    description TEXT
);
CREATE UNIQUE INDEX uq_perm_code ON permission (perm_code);

CREATE TABLE role_permission (
    role_id       BIGINT NOT NULL REFERENCES role (id),
    permission_id BIGINT NOT NULL REFERENCES permission (id),
    PRIMARY KEY (role_id, permission_id)
);

CREATE TABLE user_role (
    user_id  BIGINT NOT NULL REFERENCES app_user (id),
    role_id  BIGINT NOT NULL REFERENCES role (id),
    PRIMARY KEY (user_id, role_id)
);

-- 数据权限：按可见范围控制
CREATE TABLE data_policy (
    id          BIGINT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
    tenant_id   BIGINT NOT NULL DEFAULT 0,
    subject_type TEXT  NOT NULL,   -- user / role
    subject_id  BIGINT NOT NULL,
    scope_type  TEXT   NOT NULL,   -- datasource / database / schema / table
    scope_fqn   TEXT   NOT NULL,   -- '*' 表示全部
    effect      TEXT   NOT NULL DEFAULT 'allow',  -- allow / deny
    actions     JSONB  NOT NULL DEFAULT '["read"]'::jsonb,
    created_at  TIMESTAMPTZ NOT NULL DEFAULT now()
);
CREATE INDEX idx_dpolicy_subject ON data_policy (subject_type, subject_id);
CREATE INDEX idx_dpolicy_scope ON data_policy (scope_type, scope_fqn);

-- 业务库账号与平台用户的关联（FR-6.7）
CREATE TABLE account_user_mapping (
    id          BIGINT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
    account_id  BIGINT NOT NULL,
    user_id     BIGINT NOT NULL REFERENCES app_user (id),
    created_at  TIMESTAMPTZ NOT NULL DEFAULT now()
);
CREATE UNIQUE INDEX uq_acctuser ON account_user_mapping (account_id, user_id);
```

## 4. 核心设计

### 4.1 认证

| 项 | 方案 |
|---|---|
| 本地认证 | 口令哈希（argon2 / bcrypt），禁明文 |
| 外部认证 | 预留 `auth_source`（LDAP / OAuth），接口可扩展 |
| API 认证 | JWT（访问令牌 + 刷新令牌）；服务间调用用独立凭据 |
| CORS | **须收紧**（当前 `api/app.py:106` 为 `allow_origins=["*"]`） |

### 4.2 功能权限（RBAC）

权限码设计（细粒度，便于组合）：

| 权限 | 说明 |
|---|---|
| `datasource:read` / `datasource:write` | 数据源查看 / 管理 |
| `metadata:read` | 元数据查看 |
| `sample:execute` | 执行采样（敏感） |
| `sample:view_raw` | 查看未脱敏样本（高危） |
| `profile:read` | 查看画像 |
| `classification:read` / `:write` | 查看 / 标注分级 |
| `lineage:read` | 查看血缘 |
| `permission:read` | 查看权限分析 |
| `change:read` / `:ack` | 查看 / 确认变更 |
| `audit:read` | 查看审计 |
| `export:execute` | 导出（敏感） |

内置角色：管理员、治理员、分析师、只读用户。

### 4.3 数据权限（FR-10.5，关键）

**下推到查询条件，而非应用层过滤**：

```
用户请求 → MOD-11 解析其 data_policy → 生成可见 scope（数据源/库/表 FQN 前缀集合）
        → 作为 WHERE 条件下推给 MOD-09 的查询
```

**禁止**先查全量再过滤（千万级下不可行，且会打乱分页）。

实现要点：

- `scope_fqn='*'` 表示全部可见
- `deny` 优先于 `allow`
- 可见 scope 解析结果按用户缓存（短期 TTL），策略变更时失效
- 无匹配策略时默认**不可见**（最小权限）

### 4.4 多租户（FR-10.3）

- 所有业务表已有 `tenant_id`（数据模型设计约定，默认 0）
- 查询层统一注入 `tenant_id` 过滤
- 租户间数据完全隔离；超管角色可跨租户（可选）

### 4.5 与 MOD-08 的关联（FR-6.7）

`account_user_mapping` 把业务库账号映射到平台用户，使得：

- 权限分析可定位到真实责任人
- 变更通知可推送到责任人（而非仅账号名）

MOD-08 对本模块的依赖**可降级**：本模块未上线时，MOD-08 退化为按账号名匹配。

### 4.6 审计

所有权限相关操作（授权变更、登录、策略修改）、以及经本模块鉴权的敏感操作（采样、导出），均经 MOD-10 审计。

## 7. 关键设计决策

| # | 决策 | 理由 |
|---|---|---|
| D1 | RBAC + 数据策略分离 | 功能权限（能做什么）与数据权限（能看什么）是正交维度，混在角色里会导致角色爆炸 |
| D2 | 数据权限下推到 SQL | 应用层过滤在千万级下不可行且打乱分页 |
| D3 | 无匹配策略默认不可见 | 最小权限原则；配置遗漏不应导致越权 |
| D4 | 保留 `tenant_id` 即便单租户 | 预留成本极低，后期多租户改造代价极高（Q4） |
| D5 | 敏感操作单独授权（采样、查看原文、导出） | 这些动作直接触碰业务数据，不应随「只读」角色默认开放 |
| D6 | 本模块排期 P3 且其他模块对其依赖可降级 | 避免阻塞 P0/P1 模块交付 |

## 8. 异常与边界处理

| 场景 | 处理 |
|---|---|
| 未认证请求 | 401；除健康检查等白名单 |
| 权限不足 | 403，明确提示缺失的权限码 |
| 数据策略冲突（allow + deny） | deny 优先 |
| 策略未配置 | 默认不可见 |
| 令牌过期 | 401 + 引导刷新 |
| 用户被禁用 | 立即失效（校验时查状态，非仅靠令牌） |
| 跨租户访问 | 拒绝并审计 |

---

## 9. 验收标准

1. 所有 API 需认证（白名单除外），未认证返回 401
2. CORS 收紧到显式域名
3. 功能权限按角色生效，越权返回 403
4. 数据权限按数据源/库/表粒度生效，且下推至查询层
5. 无策略用户默认看不到任何资产
6. 敏感操作（采样、查看原文、导出）需单独授权
7. 业务库账号可关联到平台用户
8. 所有权限与敏感操作有审计记录
