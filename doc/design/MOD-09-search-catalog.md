# MOD-09 检索与资产目录 · 详细设计

| 项目 | 内容 |
|---|---|
| 模块编号 | MOD-09 |
| 负责需求 | FR-11、FR-14 |
| 优先级 | P0（用户唯一直接触达面） |
| 依赖模块 | MOD-02、04、05、06、07、08（读）；MOD-11（权限过滤）；MOD-10（审计、缓存） |
| 被依赖 | 无（终端消费模块） |

---

## 1. 职责与边界

### 1.1 职责

1. **全局检索**：表/字段的模糊与精准检索
2. **多维筛选与浏览**：按数据源、库、schema、类型、分级、标签、负责人
3. **资产详情聚合视图**：把分散在各模块的资产信息聚合为一张卡片
4. **概览统计**：资产总量、分级分布、质量分布、敏感资产占比
5. **业务元数据**：术语表、业务描述、别名、业务标签（FR-14）
6. **数据预览**：经 MOD-03 获取脱敏样本行

### 1.2 边界（不做）

- 不采集、不计算、不判定——**只读取与聚合**各模块结果
- 不做平台自身权限管理（属 MOD-11），只调用其过滤能力
- 不做分级识别（属 MOD-05），只写 `business` 命名空间标签

## 3. 数据模型

**本模块独占写**：

| 表 | 用途 |
|---|---|
| `business_term` | 业务术语/指标定义 |
| `business_metadata` | 实体业务描述、别名、业务域、业务负责人 |
| `entity_tag`（`business.*`） | 业务标签（与 MOD-05 的 `security.*` 隔离） |

```sql
CREATE TABLE business_term (
    id          BIGINT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
    tenant_id   BIGINT NOT NULL DEFAULT 0,
    term_code   TEXT   NOT NULL,
    term_name   TEXT   NOT NULL,
    domain      TEXT,
    definition  TEXT,
    owner       TEXT,
    status      TEXT   NOT NULL DEFAULT 'active',
    created_at  TIMESTAMPTZ NOT NULL DEFAULT now(),
    updated_at  TIMESTAMPTZ NOT NULL DEFAULT now()
);
CREATE UNIQUE INDEX uq_bterm_code ON business_term (term_code);

CREATE TABLE business_metadata (
    id             BIGINT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
    tenant_id      BIGINT NOT NULL DEFAULT 0,
    entity_type    TEXT   NOT NULL,   -- table / column
    entity_id      BIGINT NOT NULL,
    alias          TEXT,
    business_desc  TEXT,
    domain         TEXT,
    owner_business TEXT,
    term_codes     JSONB  NOT NULL DEFAULT '[]'::jsonb,
    created_at     TIMESTAMPTZ NOT NULL DEFAULT now(),
    updated_at     TIMESTAMPTZ NOT NULL DEFAULT now()
);
CREATE UNIQUE INDEX uq_bmeta_entity ON business_metadata (entity_type, entity_id);
CREATE INDEX idx_bmeta_domain ON business_metadata (domain);
CREATE INDEX idx_bmeta_alias ON business_metadata USING gin (alias gin_trgm_ops);
```

> 已同步至 `02-schema-ddl.sql`。
> **为什么不把业务描述写到 `catalog_table`**：`catalog_*` 的 Owner 是 MOD-02，若 MOD-09 也写会造成双写冲突（总览约束）。独立表保持单一写者。

**只读**：`catalog_*`、`table_profile`、`quality_result`、`entity_tag`、`classification_tag`、`change_event`、`lineage_*`、`account_grant`。

## 4. 核心设计

### 4.1 检索实现

| 检索类型 | 实现 | 索引 |
|---|---|---|
| 表名/字段名模糊 | `ILIKE '%kw%'` | `gin_trgm_ops`（`pg_trgm`） |
| FQN 前缀 | `fqn LIKE 'prefix%'` | btree + `text_pattern_ops` |
| 标签筛选 | `tags @> '["x"]'` | `jsonb_path_ops` |
| 分级筛选 | `grade_level >= n` | btree |
| 组合筛选 + 排序 | 排序键索引前缀匹配 | 复合索引（见设计文档 §6.2） |

**分页**：一律 keyset 游标。排序键与索引前缀必须一致，否则退化为全表排序。

**深翻限制（FR-11.7）**：模糊搜索无稳定游标，限制结果上限（1000 条 / 50 页），超出提示收窄条件。列表浏览（有稳定排序键）可无限翻页。

**中文检索**：`pg_trgm` 对中文子串效果有限，需实测；必要时引入 `pg_bigm`（设计文档 §11 待细化项）。

### 4.2 资产详情聚合（关键性能点）

详情视图需要聚合 6 个模块的数据：

```
表详情 = 结构（MOD-02 字段列表）
       + 画像（MOD-04 table_profile）
       + 质量（MOD-04 quality_result）
       + 分级（MOD-05 entity_tag + grade）
       + 业务（MOD-09 business_metadata）
       + 变更（MOD-06 change_event 近期）
       + 血缘摘要（MOD-07 一度上下游）
       + 授权（MOD-08 account_grant）
```

**禁止串行 N+1 查询**。做法：

1. 单次详情：各模块查询**并发发起**（异步并发或线程池），耗时取最大值而非累加
2. 列表场景：**不加载**画像/血缘/变更等重数据，只返回主表字段 + 分级；详情按需加载
3. 高频统计（概览、分级分布）：结果缓存（短期 TTL），避免每次全表 count

### 4.3 概览统计

| 统计项 | 实现 |
|---|---|
| 资产总量（表/字段数） | 缓存 + `pg_class.reltuples` 近似值 |
| 分级分布 | `grade_level` 分组计数（有索引） |
| 敏感资产占比 | `grade_level >= 阈值` 占比 |
| 质量分布 | `quality_result` 聚合 |
| 变更趋势 | `change_event` 按时间聚合 |

统计走定时任务预计算 + 缓存，不在请求内实时全表聚合。

### 4.4 数据权限过滤（与 MOD-11）

所有检索与详情接口**必须**先经 MOD-11 获取可见范围（数据源/库/表级），再下推到查询条件：

```
用户请求 → MOD-11 返回可见 scope → 作为 WHERE 条件下推 → 查询
```

**禁止**「先查全量再在应用层过滤」——千万级下不可行，且分页会被打乱。

### 4.5 样本预览

经 MOD-03 `RowSampler.sample_rows(table_id, limit)` 获取**已脱敏**样本行。需审计（MOD-10）——预览真实数据是敏感操作。

## 7. 关键设计决策

| # | 决策 | 理由 |
|---|---|---|
| D1 | 业务元数据独立表，不写 `catalog_*` | 保持单一写者（总览约束），避免与 MOD-02 双写冲突 |
| D2 | 详情聚合并发查询，禁止串行 N+1 | 8 个数据源串行会拖垮详情接口 |
| D3 | 列表不加载重数据 | 列表接口 QPS 最高，加载画像/血缘会放大千万倍 |
| D4 | 权限过滤下推到 SQL，而非应用层过滤 | 应用层过滤在千万级下不可行且打乱分页 |
| D5 | 统计预计算 + 缓存 | 实时全表聚合无法支撑页面加载 |
| D6 | 模糊搜索限制深度 | keyset 无法用于模糊匹配，业界通行做法 |
| D7 | 对 MOD-07/08/11 依赖可降级 | 三者排期靠后，不能阻塞 P0 模块 |

## 8. 异常与边界处理

| 场景 | 处理 |
|---|---|
| 搜索结果过多 | 上限截断 + 提示收窄条件 |
| 某模块不可用（如血缘未上线） | 详情中该区块标记不可用，其余正常 |
| 缓存失效 | 回源查询，限流保护 |
| 用户无权限 | 由 MOD-11 过滤；空结果返回空列表而非错误 |
| 详情中表已被删除 | 返回软删除标记，提示资产已下线 |
| 样本预览触发频繁 | 限流 + 审计 |

---

## 9. 验收标准

1. 千万级字段上表名/字段名模糊检索 P95 < 500ms
2. 列表分页全程 keyset，无深 OFFSET
3. 详情聚合接口并发取数，P95 达标
4. 多维组合筛选结果正确且走索引
5. 概览统计有缓存，页面加载不触发全表聚合
6. 业务描述/别名/术语可维护且可按别名检索
7. 业务标签与安全标签互不覆盖（命名空间隔离生效）
8. MOD-07/08/11 未上线时本模块可正常服务
9. 样本预览脱敏且有审计
