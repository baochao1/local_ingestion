# MOD-05 元数据分类分级 · 详细设计

| 项目 | 内容 |
|---|---|
| 模块编号 | MOD-05 |
| 负责需求 | FR-9（含 `04` 补充项 FR-9.9 ~ FR-9.11） |
| 优先级 | P1 |
| 依赖模块 | MOD-03（值样本 C4）、MOD-02（元数据、grade 回写通道）、MOD-10（任务、审计） |
| 被依赖 | MOD-09（展示与筛选）、MOD-08（高敏资产标注）、MOD-11（数据权限参考） |

---

## 1. 职责与边界

### 1.1 职责

1. **分级标准管理**：等级与类别定义（可自定义，如 L1–L4 / 公开-核心）
2. **识别规则管理**：词典、正则、类型启发式、采样回验规则
3. **识别引擎**：对表与字段自动打标，输出敏感等级
4. **结果回写**：写 `entity_tag`（`security` 命名空间）与 `catalog_column.grade_level`
5. **误报反馈闭环**与**覆盖率统计**

### 1.2 边界（不做）

- 不做采样（由 MOD-03 提供值样本）
- **不做业务标签**（属 MOD-09，`business` 命名空间）
- 不直接调用 MOD-03 停止采样 —— 通过 MOD-10 下发异步任务（避免循环依赖）
- 不修改元数据实体结构字段（只回写 `grade_level` / `grade_code`）

## 3. 数据模型

| 表 | 用途 | 所有权 |
|---|---|---|
| `classification_tag` | 分级标准与标签定义 | **本模块写** |
| `classification_rule` | 识别规则 | **本模块写** |
| `entity_tag`（`security.*`） | 打标结果 | **本模块写（仅 security 命名空间）** |
| `catalog_column.grade_level/grade_code` | 冗余列，供筛选 | **本模块写（仅此两列）** |
| `catalog_table.grade_level/grade_code` | 表级聚合冗余 | **本模块写（仅此两列）** |

**命名空间约束**：`entity_tag` 中本模块只读写 `security.*`；`business.*` 属 MOD-09，本模块不得触碰（总览约束 A）。

**列写入约束**：回写时只更新 `grade_level` / `grade_code`，禁止整行覆盖，避免抹掉 MOD-02 写入的结构信息（总览约束 B）。

## 4. 核心设计

### 4.1 识别流程

```
[任务触发：定时 / 扫描后编排 / 手动重跑]
   │
   ├─ 1. 取待识别字段（全量 / 增量：仅 struct_hash 变化或新增的字段）
   ├─ 2. 四层识别（逐层累积置信度）：
   │     ├─ L1 字段名词典：name 命中词典（phone/mobile/id_card...）
   │     ├─ L2 正则规则：命中手机号/身份证/邮箱等模式
   │     ├─ L3 类型启发式：varchar(18)、char(11) 等类型+长度组合
   │     └─ L4 采样回验：调用 MOD-03 C4 取该列 distinct 样本，用规则回验
   ├─ 3. 置信度合成：多策略命中取加权合成，得到最终置信度
   ├─ 4. 判定等级：命中标签 → 取对应 grade_level
   ├─ 5. 写入：
   │     ├─ entity_tag（source='rule'/'sample'，confidence，applied_at）
   │     ├─ catalog_column.grade_level / grade_code（冗余）
   │     └─ 表级：聚合字段最高等级 → catalog_table.grade_level
   ├─ 6. 高敏判定 → 若达到熔断阈值，经 MOD-10 下发「停止采样 + 清除样本」任务
   └─ 7. 覆盖率统计
```

**采样回验（L4）是降低误报的关键**：仅靠字段名会把 `phone_type`（类型枚举）误判为手机号；用真实样本值回验正则可大幅降低误报。

### 4.2 置信度合成

| 策略 | 基础置信度 | 说明 |
|---|---|---|
| 字段名词典 | 0.6 | 易误报（如 `phone_status`） |
| 正则（字段名） | 不适用 | 字段名不跑正则 |
| 类型启发式 | 0.4 | 弱信号 |
| 采样值回验 | 0.9 | 强信号（真实数据命中） |

合成规则：**取最高命中策略的置信度**；若采样回验命中则直接采纳高置信（0.9+）；若仅词典命中而采样回验未命中，则降权（如 0.6 → 0.3）并标记低置信。

低置信结果：仍打标但标记 `confidence` 低值，供人工复核；不触发熔断。

### 4.3 人工修正优先（FR-9.5）

| 场景 | 处理 |
|---|---|
| 自动引擎遇到 `source='manual'` 的标签 | **跳过，不覆盖** |
| 人工修改等级 | 写入 `source='manual'`，同时使同标签的自动结果失效（`deleted_at`） |
| 人工确认为「非敏感」 | 写入负向标签（如 `security.NOT_SENSITIVE`），引擎后续跳过该字段 |

### 4.4 表级等级聚合

表级 `grade_level` = 其所有字段 `grade_level` 的**最大值**；字段升级/降级后触发表级重算。任务内批量重算，避免逐表 SQL。

### 4.5 独立重跑（FR-9.7）

引擎为**独立异步任务**，非挂在扫描 Sink 上（ADR-4）：

- 规则迭代后对存量全量或按数据源重跑
- 重跑前清除 `source IN ('rule','sample')` 的旧标签，保留 `manual`
- 重跑结果可与上次比对，输出差异（用于误报反馈验证，FR-9.10）

### 4.6 高敏熔断的调用路径

```
MOD-05 判定 grade ≥ 阈值
   → 写 catalog_column.grade_level（表）
   → 经 MOD-10 下发异步任务 → MOD-03 purge_samples(column_ids)
```

**MOD-03 侧则在每次采样前读 `grade_level` 自行熔断**。两侧都不直接调用对方，循环依赖被打破（总览 §5.1）。

## 7. 关键设计决策

| # | 决策 | 理由 |
|---|---|---|
| D1 | 引擎独立异步，不做成 Sink（ADR-4） | Sink 是单向终点，无法表达「读—打标—回写」；独立引擎支持规则迭代后重跑，无需全库重扫 |
| D2 | 四层识别 + 采样回验 | 纯词典误报率高；真实样本回验是准确率的关键 |
| D3 | 置信度随策略分级 | 不同信号强度不同，合成后才能支撑低置信复核 |
| D4 | 人工优先且负向标签 | 人工修正被自动扫描覆盖是分级产品最常见的投诉点 |
| D5 | `security` / `business` 命名空间隔离 | `entity_tag` 有两个写者，不隔离必互相覆盖 |
| D6 | 熔断经 MOD-10 异步 | 打破 MOD-03 ↔ MOD-05 循环依赖 |
| D7 | 只回写 grade 两列 | 保护 MOD-02 的结构字段（总览约束 B） |

---

## 8. 异常与边界处理

| 场景 | 处理 |
|---|---|
| 多规则命中不同等级 | 取最高等级；记录所有命中标签供审计 |
| 置信度低于阈值 | 打标但标记低置信，进入人工复核队列 |
| 采样不可用（源不支持/被熔断） | 降级为三层识别（无采样回验），标记 `degraded` |
| 分级标准变更 | 记录版本；可选择对存量重算或仅影响新增 |
| 人工与自动冲突 | 人工优先，自动结果失效并记录 |
| 表无字段（异常） | 表级等级置空 |
| 规则正则性能问题 | 规则执行限流；正则需预校验复杂度 |

---

## 9. 验收标准

1. 常见 PII 字段（手机号、身份证、邮箱、银行卡）识别准确率达标
2. 采样回验可将纯词典误报显著降低（有前后对比数据）
3. 人工标注不被自动重跑覆盖
4. 高敏字段自动触发采样熔断且已有样本被清除
5. 表级等级正确聚合自字段最高等级
6. 规则迭代后可对存量重跑，并输出与上一版的差异
7. 分级覆盖率可统计
8. 敏感资产清单可导出
