## 1. 问题

三个"跑得出来但没有下文"的能力：

| 能力 | 现状 | 证据 |
|---|---|---|
| **数据质量** | 7 类规则已定义，但**在内存中执行、结果不落库**；结果表已建未接 | `quality/rules.py`；`storage/models_governance.py:193` |
| **分类分级** | 自动分级达标（亮点），但**只有列名启发式**，误报直接进下游策略；且结果唯一出口是筛选 | `platform/classification/rules.py:57-75`；`product-benchmark-roadmap.md` 判断三 |
| **任务状态** | 无"部分成功"中间态，部分失败被显示为整体失败 | `platform/orchestration/service.py` |

`product-benchmark-roadmap.md` 的反模式警示：**误报 → 脱敏 → 业务故障**。本 spec 的 FR-M6 是这条链路上的止损点。

---

## 2. 目标与非目标

**目标**：质量可追溯、分级可复核、任务状态可分辨。

**非目标**

| 项 | 理由 |
|---|---|
| 引入 NER / Presidio / spacy 做 PII 识别 | 总纲 §2.3.6：只移植值模式，不引 NLP 运行时 |
| 引入 `great_expectations` | 重依赖，非目标 |
| 数据契约 / 策略引擎（分级驱动脱敏、权限） | 属更大范围；本 spec 只做"分级结果可信"，不做"分级驱动策略" |
| 推翻重建现有自动分级 | `product-benchmark-roadmap.md` 判断一：现有自动分级是亮点，本 spec 为**增强** |

---

## 3. 约束

继承总纲 C1~C8，额外：

| # | 约束 |
|---|---|
| QC1 | **不得为分级新增任何取数动作**：值模式验证只复用已采集样本（原风险 R-M2 提升为需求） |
| QC2 | 质量用例失败行样本含敏感数据时，须按既有脱敏策略处理后再展示 |
| QC3 | `pandas` 不得从 `dev` extra 提升为运行时依赖 |
| QC4 | 分级判定必须**可解释**：给出命中依据，不得只给结果 |

## 4. 用户场景

| 角色 | 场景 | 期望 |
|---|---|---|
| 数据治理 | 某质量用例失败了 | 看到失败行数、比例与**失败行样本**，直接定位问题数据 |
| 数据治理 | 定期看质量趋势 | 看到用例成功率趋势与最近失败列表 |
| 数据治理 | 一张表 200 个字段要复核 | 按置信度区间**批量确认/批量修正**，而非逐个点 |
| 数据治理 | 某个字段被判为敏感，怀疑是误报 | 看到命中依据（列名 / 值模式 / 两者），据以判断 |
| 数据平台/DBA | 一个 3 步任务第 2 步失败 | 任务显示"部分成功"，第 1、3 步结果仍可查看 |

## 5. 功能需求

### FR-M5 数据质量用例化与结果留存

| # | 需求 |
|---|---|
| FR-M5.1 | 质量检查以**用例**为单位管理：绑定资产 + 规则类型 + 参数 + 阈值，可启停 |
| FR-M5.2 | 执行优先**下推到数据源**；不支持时退化为取样本数据在内存中执行 |
| FR-M5.3 | 结果**持久化**：状态、指标值、通过/失败行数与比例、耗时、错误信息 |
| FR-M5.4 | 失败用例可采集并展示**失败行样本** |
| FR-M5.5 | 提供用例成功率趋势与最近失败列表 |
| FR-M5.6 | 规则类型至少覆盖：空值、唯一、范围、集合、正则、长度、行数、列存在、自定义 SQL |

### FR-M6 分类分级：值模式验证与置信度

| # | 需求 |
|---|---|
| FR-M6.1 | 在列名启发式之上增加**基于采样值的值模式验证**，两者共同决定判定 |
| FR-M6.2 | 每条判定**输出置信度与命中依据**（列名命中 / 值模式命中 / 两者同时命中）（QC4） |
| FR-M6.3 | 提供置信度阈值配置；低于阈值的判定标记为"待复核"而非直接生效 |
| FR-M6.4 | 对高基数且明显无模式的列（如主键）**跳过值模式扫描**，控制开销 |
| FR-M6.5 | 复核界面支持**按置信度区间批量确认/批量修正** |
| FR-M6.6 | 分级结果按级别分级审批：低级免审直接生效，高级走既有审批流 |
| FR-M6.7 | **合规红线**：值模式验证只复用已采集样本，**不得为分级新增取数**；样本按既有脱敏与留存策略处理（QC1） |

### FR-M9 任务编排：部分成功态

| # | 需求 |
|---|---|
| FR-M9.1 | 任务生命周期增加"**部分成功**"中间态，与成功/失败区分展示 |
| FR-M9.2 | 任务结果包含**步骤级成功率**，失败步骤可定位 |
| FR-M9.3 | 列表与详情可区分"完全失败"与"部分失败"，后者允许查看已成功部分的结果 |

## 7. 验收标准

- **AC-5.1**：定义"某列非空"用例并执行，结果落库且含通过/失败行数。
- **AC-5.2**：制造失败数据后，结果页展示失败行样本；敏感列已脱敏（QC2）。
- **AC-5.3**：同一用例连续执行 5 次后，成功率趋势图与列表数据一致。
- **AC-6.1**：对含手机号、邮箱、随机 UUID 主键的样本集，手机号/邮箱被判为敏感且给出值模式依据；**UUID 主键不被判为敏感**。
- **AC-6.2**：值模式扫描列数相对全表列数有明确收敛，任务日志可核对（QC-N1）。
- **AC-6.3**：低于阈值的判定进入"待复核"队列，且可批量确认。
- **AC-6.4**：既有"扫描后自动分级、新字段自动获得级别"行为**不被破坏**（回归）。
- **AC-6.5**：**分级任务执行期间，对业务库发起的查询数量与关闭值模式验证时完全相同**（证明未新增取数，QC1）。
- **AC-9.1**：3 步骤任务中第 2 步失败时，状态为"部分成功"，第 1、3 步结果可查。
- **AC-9.2**：既有任务的重试、取消、并发、锁行为不受影响（回归）。

## 8. 边界情况

### 8.1 阻塞设计

| # | 情况 | 期望行为 |
|---|---|---|
| E1 | **采样样本恰好未命中敏感值** | 判定置信度低 → 进入待复核，**不得判定为"非敏感"** |
| E2 | 失败行样本含敏感数据 | 按脱敏策略处理后展示（QC2） |
| E3 | 高基数列（主键、UUID） | 跳过值模式扫描（FR-M6.4） |
| E4 | 数据源不支持下推执行 | 退化为样本数据内存执行，并在结果中标记执行方式 |

### 8.2 展示与运维

| # | 情况 | 期望行为 |
|---|---|---|
| E5 | 一列同时命中列名与值模式 | 置信度叠加，命中依据同时记录两者（FR-M6.2） |
| E6 | 用户手工修正过的分级 | 不被后续自动分级覆盖（既有"人工修正优先"设计，回归要求） |
| E7 | 用例绑定的列被删除 | 用例标记为失效并提示，不静默失败 |
| E8 | 任务全部步骤失败 | 仍为"失败"，不得显示"部分成功" |
