## 1. 问题

检索目前只能"**先知道表名，再搜**"（`platform/search/repository.py:82` 仅有关键词 + 过滤项，无聚合）。这与"让用户发现自己有什么数据"的目标直接冲突：用户拿不到任何可用于收敛的线索。

`product-benchmark-roadmap.md` §3.2 已判定主入口应为「层级浏览 + 全局搜索并列」；本特性补的是全局搜索这半边的**收敛能力**。

---

## 2. 目标与非目标

**目标**：让用户在不知道表名的前提下，通过分面计数逐级收敛到目标资产。

**非目标**

| 项 | 理由 |
|---|---|
| 引入 Elasticsearch | 重基础设施；本特性要求用关系库聚合实现 |
| 高级查询构建器（字段/操作符/值三元组） | 交互过重，当前 `FilterBar` 已够用 |
| 搜索结果高亮、拼音/模糊纠错 | 不在本特性范围 |

---

## 3. 约束

继承总纲 C1~C8，额外：

| # | 约束 |
|---|---|
| FC1 | facet 计数**必须与当前结果集一致**：已应用过滤条件后，facet 应基于过滤后的集合重新计算（或明确声明为全局计数） |
| FC2 | facet 计数**必须受权限过滤约束**：用户不得通过 facet 计数推断出自己无权查看的资产数量 |
| FC3 | 不得为 facet 引入新的检索引擎依赖 |
| FC4 | 列表仍强制 keyset 游标分页（ADR-5），facet 不得改变分页语义 |

---

## 4. 用户场景

| 角色 | 场景 | 期望 |
|---|---|---|
| 数据分析 | 只知道"大概是订单相关的表，在哪个库忘了" | 搜索"order"，看数据源/库分面计数，点进最可能的库，再按类型收敛 |
| 数据治理 | 想找出所有 L4 以上的敏感表 | 按分级分面筛选，看到各级别计数，直接进 L4 |
| 安全审计 | 想看某负责人名下有多少资产 | 按负责人分面查看计数并进入 |
| 任何人 | 条件选错了想撤销 | 已选条件以 chip 常驻，可单个移除或整体清空；刷新/分享 URL 后条件保持 |

---

## 5. 功能需求

| # | 需求 |
|---|---|
| FR-M3.1 | 检索结果同时返回各维度**命中计数**：数据源、库/schema、资产类型、分级、标签、负责人 |
| FR-M3.2 | 点击任一 facet 值即在当前结果集内叠加过滤，可多级叠加，并支持逐个移除 |
| FR-M3.3 | 已选过滤条件以 chip 形式常驻可见，并可整体清空 |
| FR-M3.4 | 过滤条件与排序**同步到 URL**，支持分享/刷新后保持 |
| FR-M3.5 | 结果超过上限时提示用户收窄条件，而非静默截断 |

---

## 6. 非功能需求

| # | 需求 |
|---|---|
| NFR-M2 | 引入 facet 后，同一查询在相同数据量下的 P95 延迟相对**上线前基线**不超过 **1.5 倍**；超出须提供降级开关 |
| NFR-M6 | 既有单测不得失败；L1 文件不得被修改 |
| FC-N1 | facet 查询与结果查询的执行计划须可审查（避免为六个维度各跑一次全表扫描） |

---

## 7. 验收标准

- **AC-3.1**：一次检索返回后，六个维度的计数与直接在库上聚合的结果一致。
- **AC-3.2**：叠加三个 facet 条件后复制 URL 到新标签页，结果集与过滤态完全一致。
- **AC-3.3**：facet 引入后 P95 延迟相对基线不超过 1.5 倍；超出时可关闭 facet。
- **AC-3.4**：以低权限账号检索，facet 计数不包含其无权查看的资产（FC2）。
- **AC-3.5**：已应用过滤后，facet 计数反映过滤后的集合（或按 FC1 明确声明的口径）。

---

## 8. 边界情况

### 8.1 阻塞设计

| # | 情况 | 期望行为 |
|---|---|---|
| E1 | 某维度取值极多（如 owner 上千、标签数百） | 按计数排序取 Top N 并提供展开；不做无限列表 |
| E2 | 已叠加多个过滤条件 | 明确 facet 计数口径（过滤后 vs 全局），并在界面可理解（FC1） |
| E3 | 用户权限受限 | facet 计数必须已在权限过滤后的集合上计算（FC2） |

### 8.2 展示

| # | 情况 | 期望行为 |
|---|---|---|
| E4 | 某维度在当前结果集中无任何取值 | 该维度不展示或展示为空态，不报错 |
| E5 | 结果集超过上限 | 提示收窄条件（FR-M3.5） |
| E6 | URL 中出现非法/过期的 facet 值 | 忽略并给出提示，不返回空结果集而不解释 |

## 9. 假设与依赖

| # | 假设 | 若不成立 |
|---|---|---|
| A1 | 千万级字段量下，关系库聚合能满足 1.5 倍延迟约束 | 需重新评估是否引入专用检索引擎（当前为非目标，属**范围变更**） |
| A2 | 六个维度的基数可控（Top N 足够） | 需改为异步加载或搜索式维度选择 |
| A3 | 总纲 OQ-0 法务结论为"可行" | 不影响本特性（facet 为自研，非移植），可从阻塞中豁免 |

> **注**：本特性**不移植上游代码**，仅借鉴交互模型。因此 A3 对本特性不构成阻塞——这是本 spec 相对其他三份的一个优势，可作为法务结论未定时的优先启动项。
